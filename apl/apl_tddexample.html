DB 쿼리 TDD란?
일반 TDD처럼 "테스트 먼저 → 실패 확인 → 본 쿼리 작성 → 통과 확인" 사이클을 DB 쿼리에 적용하는 방식입니다.

쿼리 결과가 기대값과 일치하는지 검증 쿼리를 먼저 작성하고, 본 쿼리가 그 조건을 만족시키면 완성으로 간주합니다.
① 기대값 정의
→
② 검증 쿼리 작성
→
③ 실패 확인 (RED)
→
④ 본 쿼리 작성
→
⑤ 통과 확인 (GREEN)
→
⑥ 리팩토링
RED — 실패 상태 (기대값 불일치)
-- 검증 쿼리 먼저 작성 -- 기대: A부서 계약건수 = 150 SELECT CASE WHEN COUNT(*) = 150 THEN 'PASS' ELSE 'FAIL: ' || COUNT(*) END AS test_result FROM tb_contract WHERE dept_cd = 'A001' AND base_ym = '202503'; -- 결과: FAIL: 0 ← 아직 데이터 없음
GREEN — 통과 상태 (기대값 일치)
-- 본 쿼리(INSERT/배치) 실행 후 재검증 SELECT CASE WHEN COUNT(*) = 150 THEN 'PASS' ELSE 'FAIL: ' || COUNT(*) END AS test_result FROM tb_contract WHERE dept_cd = 'A001' AND base_ym = '202503'; -- 결과: PASS ← 통과
핵심 원칙 : 검증 쿼리는 항상 PASS / FAIL 을 문자열로 반환하게 작성합니다. 숫자만 반환하면 기대값을 외워야 해서 주니어들이 실수합니다.
테스트용 샘플 테이블 및 데이터 세팅
실제 운영 테이블 건드리지 않고, 아래 테스트 테이블로 먼저 연습합니다.
-- 1. 계약 테이블 CREATE TABLE t_contract ( contract_no VARCHAR2(20) NOT NULL, base_ym CHAR(6) NOT NULL, -- 기준년월 YYYYMM dept_cd VARCHAR2(10), -- 부서코드 status_cd VARCHAR2(10), -- ACTIVE / CANCEL premium_amt NUMBER(15,2), -- 보험료 reg_dt DATE DEFAULT SYSDATE ); -- 2. 사업비 원천 테이블 CREATE TABLE t_cost_source ( base_ym CHAR(6) NOT NULL, cost_item_cd VARCHAR2(20) NOT NULL, -- 사업비 항목코드 cost_item_nm VARCHAR2(100), cost_amt NUMBER(15,2), -- 사업비 금액 alloc_type VARCHAR2(20) -- 배분방식: CONTRACT/PREMIUM/EQUAL ); -- 3. 배분 결과 테이블 CREATE TABLE t_cost_alloc_result ( base_ym CHAR(6) NOT NULL, cost_item_cd VARCHAR2(20) NOT NULL, dept_cd VARCHAR2(10) NOT NULL, alloc_ratio NUMBER(10,6), -- 배분율 (소수) alloc_amt NUMBER(15,2), -- 배분금액 reg_dt DATE DEFAULT SYSDATE );
샘플 데이터 INSERT
-- 계약 데이터 (3개 부서, 총 10건) INSERT INTO t_contract VALUES ('C001', '202503', 'DEPT_A', 'ACTIVE', 120000, SYSDATE); INSERT INTO t_contract VALUES ('C002', '202503', 'DEPT_A', 'ACTIVE', 150000, SYSDATE); INSERT INTO t_contract VALUES ('C003', '202503', 'DEPT_A', 'CANCEL', 80000, SYSDATE); INSERT INTO t_contract VALUES ('C004', '202503', 'DEPT_B', 'ACTIVE', 200000, SYSDATE); INSERT INTO t_contract VALUES ('C005', '202503', 'DEPT_B', 'ACTIVE', 180000, SYSDATE); INSERT INTO t_contract VALUES ('C006', '202503', 'DEPT_B', 'ACTIVE', 160000, SYSDATE); INSERT INTO t_contract VALUES ('C007', '202503', 'DEPT_C', 'ACTIVE', 300000, SYSDATE); INSERT INTO t_contract VALUES ('C008', '202503', 'DEPT_C', 'ACTIVE', 250000, SYSDATE); INSERT INTO t_contract VALUES ('C009', '202503', 'DEPT_C', 'ACTIVE', 220000, SYSDATE); INSERT INTO t_contract VALUES ('C010', '202503', 'DEPT_C', 'ACTIVE', 190000, SYSDATE); COMMIT; -- 사업비 원천 데이터 INSERT INTO t_cost_source VALUES ('202503', 'COST_001', '광고선전비', 1000000, 'CONTRACT'); INSERT INTO t_cost_source VALUES ('202503', 'COST_002', '인건비', 5000000, 'PREMIUM'); INSERT INTO t_cost_source VALUES ('202503', 'COST_003', '복리후생비', 300000, 'EQUAL'); COMMIT;
CANCEL 상태 계약(C003)을 일부러 포함했습니다. 주니어들이 WHERE status_cd = 'ACTIVE' 조건을 빠뜨리는 실수를 TDD로 잡아내는 연습에 활용하세요.
LEVEL 1 — SELECT 기초
CASE 1  전체 조회 + 조건 필터
검증 쿼리 먼저 (RED)
-- 기대: 202503 ACTIVE 계약 = 9건 SELECT CASE WHEN COUNT(*) = 9 THEN 'PASS' ELSE 'FAIL: ' || COUNT(*) END AS test_result FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE'; -- 실행 전: FAIL: 0
본 쿼리 (GREEN)
-- 실제 조회 쿼리 SELECT contract_no, dept_cd, premium_amt FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE' ORDER BY dept_cd, contract_no; -- 9건 반환 → 검증 쿼리 PASS
주니어 흔한 실수 : status_cd 조건 누락 → 10건 반환. 검증 쿼리가 FAIL: 10 을 출력해서 즉시 잡힙니다.
CASE 2  특정 부서 데이터 조회
검증 쿼리
-- 기대: DEPT_B 계약 3건, 합계 540000 SELECT CASE WHEN cnt = 3 AND tot = 540000 THEN 'PASS' ELSE 'FAIL cnt='||cnt||' tot='||tot END AS test_result FROM ( SELECT COUNT(*) cnt, SUM(premium_amt) tot FROM t_contract WHERE dept_cd = 'DEPT_B' AND base_ym = '202503' AND status_cd = 'ACTIVE' );
본 쿼리
SELECT contract_no, dept_cd, premium_amt FROM t_contract WHERE dept_cd = 'DEPT_B' AND base_ym = '202503' AND status_cd = 'ACTIVE'; -- C004: 200000 -- C005: 180000 -- C006: 160000 -- 합계: 540000 → PASS
LEVEL 2 — 집계 / GROUP BY
CASE 3  부서별 계약건수 집계
검증 쿼리
-- 기대: 부서 3개 / 전체합 9건 SELECT CASE WHEN dept_cnt = 3 AND total_cnt = 9 THEN 'PASS' ELSE 'FAIL dept='||dept_cnt||' tot='||total_cnt END AS test_result FROM ( SELECT COUNT(DISTINCT dept_cd) AS dept_cnt, COUNT(*) AS total_cnt FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE' );
본 쿼리
SELECT dept_cd, COUNT(*) AS contract_cnt, SUM(premium_amt) AS total_premium FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE' GROUP BY dept_cd ORDER BY dept_cd; -- DEPT_A: 2건 270000 -- DEPT_B: 3건 540000 -- DEPT_C: 4건 960000
CASE 4  집계 후 비율 계산 (Window Function)
검증 쿼리
-- 기대: 모든 부서 비율 합계 = 100 SELECT CASE WHEN ABS(SUM(alloc_ratio) - 100) < 0.001 THEN 'PASS' ELSE 'FAIL: 합계=' || SUM(alloc_ratio) END AS test_result FROM ( SELECT dept_cd, ROUND( COUNT(*) * 100.0 / SUM(COUNT(*)) OVER(), 6 ) AS alloc_ratio FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE' GROUP BY dept_cd );
본 쿼리
SELECT dept_cd, COUNT(*) AS contract_cnt, ROUND( COUNT(*) * 100.0 / SUM(COUNT(*)) OVER(), 6 ) AS alloc_ratio FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE' GROUP BY dept_cd; -- DEPT_A: 22.222222% -- DEPT_B: 33.333333% -- DEPT_C: 44.444444% -- 합계: 99.999999 → ABS 비교로 PASS
비율 합계 검증은 = 100 이 아니라 ABS(합계 - 100) < 0.001 로 작성해야 합니다. 소수점 반올림 오차로 99.999999가 나올 수 있어요. 이걸 모르면 주니어들이 FAIL을 보고 멘붕합니다.
LEVEL 3 — 배분 로직 구현
CASE 5  계약건수 기준 배분액 계산
-- COST_001 광고선전비 1,000,000원을 계약건수 비율로 배분 -- 기대값 : DEPT_A=222,222 / DEPT_B=333,333 / DEPT_C=444,444 -- (소수점 반올림 → 합계 999,999. 차액 1원은 최대 부서에 보정 필요) SELECT dept_cd, contract_cnt, alloc_ratio, ROUND(1000000 * alloc_ratio / 100, 0) AS alloc_amt FROM ( SELECT dept_cd, COUNT(*) AS contract_cnt, ROUND( COUNT(*) * 100.0 / SUM(COUNT(*)) OVER(), 6 ) AS alloc_ratio FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE' GROUP BY dept_cd ) ORDER BY dept_cd;
핵심 이슈  1원 차액 보정 (페니 프라블럼)
반올림으로 배분액 합계가 원천 금액과 1~2원 차이가 날 수 있습니다. 보험 결산에서는 이 오차가 허용되지 않으므로 반드시 보정 로직이 필요합니다.
-- 1원 차액 보정 : 마지막 부서에 차액 합산 SELECT dept_cd, CASE WHEN rn = max_rn THEN 1000000 - SUM(alloc_amt) OVER ( ORDER BY rn ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) ELSE alloc_amt END AS final_amt FROM ( SELECT dept_cd, ROUND(1000000 * alloc_ratio / 100, 0) AS alloc_amt, ROW_NUMBER() OVER (ORDER BY dept_cd) AS rn, COUNT(*) OVER () AS max_rn FROM ( SELECT dept_cd, ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER(), 6) AS alloc_ratio FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE' GROUP BY dept_cd ) );
이 보정 로직을 모르는 주니어가 대부분입니다. TDD 검증 쿼리에서 "배분결과 합계 = 원천금액" 조건을 넣어두면 자동으로 이슈가 드러납니다.
배치 실행 전후 필수 검증 쿼리 세트
아래 검증 쿼리를 배치 Job의 마지막 Step으로 반드시 실행합니다. 하나라도 FAIL이면 배치를 FAIL 처리합니다.
-- [CHECK 1] 배분 결과 건수 검증 (부서 수만큼 INSERT 되었는지) SELECT 'CHECK_1_건수' AS check_nm, CASE WHEN COUNT(*) = ( SELECT COUNT(DISTINCT dept_cd) FROM t_contract WHERE base_ym = '202503' AND status_cd = 'ACTIVE') THEN 'PASS' ELSE 'FAIL: ' || COUNT(*) END AS result FROM t_cost_alloc_result WHERE base_ym = '202503' AND cost_item_cd = 'COST_001' UNION ALL -- [CHECK 2] 배분 금액 합계 = 원천 금액 검증 SELECT 'CHECK_2_금액합계', CASE WHEN ABS( (SELECT SUM(alloc_amt) FROM t_cost_alloc_result WHERE base_ym = '202503' AND cost_item_cd = 'COST_001') - (SELECT cost_amt FROM t_cost_source WHERE base_ym = '202503' AND cost_item_cd = 'COST_001') ) <= 1 -- 1원 오차 허용 THEN 'PASS' ELSE 'FAIL: 금액불일치' END FROM DUAL UNION ALL -- [CHECK 3] 배분율 합계 = 100 검증 SELECT 'CHECK_3_비율합계', CASE WHEN ABS(SUM(alloc_ratio) - 100) < 0.001 THEN 'PASS' ELSE 'FAIL: ' || SUM(alloc_ratio) END FROM t_cost_alloc_result WHERE base_ym = '202503' AND cost_item_cd = 'COST_001' UNION ALL -- [CHECK 4] NULL 배분금액 존재 여부 SELECT 'CHECK_4_NULL체크', CASE WHEN COUNT(*) = 0 THEN 'PASS' ELSE 'FAIL: NULL ' || COUNT(*) || '건' END FROM t_cost_alloc_result WHERE base_ym = '202503' AND cost_item_cd = 'COST_001' AND alloc_amt IS NULL;
이 4개 CHECK를 Spring Batch의 마지막 Tasklet에 넣어두면, FAIL 항목이 하나라도 있으면 배치 상태를 FAILED로 기록하고 담당자에게 알림을 보내는 구조로 만들 수 있습니다.
주니어 체크리스트 — 쿼리 작성 전 확인 사항
항목확인 내용안 지키면
status_cd 조건 ACTIVE 조건 반드시 포함 취소 계약 포함 → 건수/금액 오류
base_ym 조건 기준년월 파라미터 바인딩 전체 기간 데이터 집계 → 성능 폭발
SELECT * 필요한 컬럼만 명시 불필요한 I/O → 성능 저하
비율 합계 검증 = 100 대신 ABS < 0.001 사용 소수점 오차로 FALSE FAIL
1원 차액 보정 마지막 부서에 차액 합산 배분 합계 ≠ 원천 금액
MERGE 사용 INSERT 대신 MERGE로 멱등성 확보 배치 재실행 시 중복 데이터
